# Local SearXNG discovery

DRAGON uses a private, local-only SearXNG instance as its preferred
provider-neutral general-search backend. The service is a discovery source;
its JSON result metadata, titles, and snippets are never evidence.

## Runtime

- Image: `docker.io/searxng/searxng@sha256:a93b665d10ce0675e8d2124187943111399ba69f384228c51b4cd21fdceda0bc`
- License: AGPL-3.0-or-later (SearXNG upstream)
- Bind: `127.0.0.1:8088` only; the container port is not publicly exposed.
- API: `GET /search?q=...&format=json`; JSON is explicitly enabled in
  `infra/searxng/settings.yml`.
- Credentials: none. A random process-local SearXNG secret is generated by
  the start script and is neither committed nor persisted in the worktree.

Start it from the repository root:

```powershell
./scripts/start_local_searxng.ps1
```

Check health with `docker ps --filter name=dragon-searxng-searxng-1`; stop it
with `./scripts/stop_local_searxng.ps1`. The health check reaches the
container's local root endpoint only. DRAGON's
bounded smoke/rehearsal requests are the only searches performed by this
deployment configuration.

If Docker or the service is unavailable, DRAGON records
`SEARCH_BACKEND_UNAVAILABLE` and continues configured routes and Google News
RSS within the existing action budget. It never treats that outage as evidence
or as a reason to relax publication gates.
